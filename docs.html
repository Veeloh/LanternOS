Syscall_Table.sys

Userland talks to the kernel with int $0x80. Load the syscall number into eax and the first argument into ebx, then trap. There's no libc and no crt0 — the loader calls your _start directly, so it's the raw ABI or nothing.

Syscall eax ebx Behavior
SYS_EXIT 0 exit code Marks the current process PROCESS_DEAD, hands off to process_schedule(), then spins on hlt forever. Never returns to the caller.
SYS_WRITE 1 char* str Prints a null-terminated string straight to the VGA text buffer via vga_print().
SYS_READ 2 — Blocks until a key is available (keyboard_getchar()). Serviced on the interrupt path rather than the generic dispatcher below — its case in syscall_handler is currently a no-op.

Dispatcher

syscall_init() wires interrupt vector 0x80 to syscall_isr. On trap, the ISR calls into syscall_handler(eax, ebx, ecx, edx), which switches on eax and dispatches: 

void syscall_handler(uint32_t eax, uint32_t ebx, uint32_t ecx, uint32_t edx) {
    switch (eax) {
        case SYS_EXIT:
            sys_exit(ebx);
            break;
        case SYS_WRITE:
            sys_write((const char*)ebx);
            break;
        case SYS_READ:
        // handled in isr
            break;
        default: vga_print("\nUnknown syscall!");
        break;
    }
}

Unrecognized syscall numbers fall through to the default case and print a warning instead of crashing.

hello.c

The minimal userland test program, found in src/user. No libc, no crt0 — _start runs directly on the kernel's stack, since elf_exec calls the entry point like a normal function. 

// hello.c - minimal SolOS userland test program.
// No libc, no crt0 - _start runs directly on the kernel's stack
// (elf_exec calls the entry point like a normal function), so we
// don't need to set up our own stack frame here.
static void sys_write(const char* str) {
    __asm__ volatile (
        "mov $1, %%eax\n"   // SYS_WRITE
        "mov %0, %%ebx\n"
        "int $0x80\n"
        :: "r"(str)
        : "eax", "ebx"
    );
}
static void sys_exit(int code) {
    __asm__ volatile (
        "mov $0, %%eax\n"   // SYS_EXIT
        "mov %0, %%ebx\n"
        "int $0x80\n"
        :: "r"(code)
        : "eax", "ebx"
    );
}
void _start() {
    sys_write("Hello from userland!\n");
    sys_exit(0);
    // sys_exit halts the process (see sys_exit() in syscall.c - it
    // marks the process dead and spins forever), so we never get
    // here. This is just a safety net in case that ever changes.
//  while (1);
}

Linker script

Userland binaries load at a fixed base. The loader refuses segments outside 0x400000–0x800000 (ELF_USER_MIN_ADDR in elf.h), so the linker script must match: 

ENTRY(_start)
SECTIONS {
    /* must match ELF_USER_MIN_ADDR in elf.h - the loader refuses
       to load segments outside 0x400000-0x800000 */
    . = 0x400000;
    .text : {
        *(.text)
    }
    .rodata : {
        *(.rodata)
    }
    .data : {
        *(.data)
    }
    .bss : {
        *(COMMON)
        *(.bss)
    }
}
menubar.h

Windowed apps register their own commands into the two built-in dropdowns instead of drawing a menu bar themselves.

typedef void (*menubar_cmd_t)(void);

A menu command: a zero-argument function pointer, run when the item is clicked.

typedef enum { MENUBAR_FILE, MENUBAR_EDIT } menubar_menu_t;

The two dropdowns currently available: File and Edit.

#define MENUBAR_MAX_ITEMS 4

Each dropdown holds at most 4 rows.

void menubar_add_item(menubar_menu_t menu, const char* title, menubar_cmd_t cmd);

Adds one row to the given dropdown. title should outlive the item — a string literal is fine, a stack buffer isn't. Silently no-ops once MENUBAR_MAX_ITEMS is hit, so watch your item count.

void menubar_clear_menu(void);

Removes every item from both dropdowns. Also closes an open dropdown, since its row count is about to change out from under it.
